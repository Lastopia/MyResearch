# 研究设计文档写作 Skill

## 适用场景

当需要在本研究项目中撰写或扩展理论设计、实验设计、机制分析、研究计划类 Markdown 文档时，优先使用本写作结构。目标是让文档保持“主线清楚、假设先行、文献支撑后置”的风格，避免正文被过长的综述材料打断。

## 总体布局

文档优先分为两个顶层部分：

```markdown
# 引言

# 设计
```

`引言` 用来交代研究背景、上一次实验教训、本次研究目标和计划实验方向。`设计` 用来按机制或模块展开具体实验设想。

## 引言部分

引言中优先使用三级标题组织内容：

```markdown
### 上个实验的教训

### 本次实验的目的
```

`上个实验的教训` 应先用简短项目符号总结上一次实验做了什么、结果如何，再用编号列表提炼可迁移的经验。重点不是复盘所有细节，而是提炼会影响下一轮研究设计的判断。

`本次实验的目的` 应先明确研究目标，再说明为了实现目标预计做哪些实验。目标和实验方向都优先使用编号列表，让读者能快速看到研究主线。

## 设计部分

设计部分按机制或模块分章节，例如：

```markdown
### Attention 的修改

### FFN 的修改

### Loss 的修改
```

每个机制章节开头先放一个简短的 `markdown` 代码块，用来压缩表达该机制的核心假设和实验思路：

```markdown
**假设**
    这里写该机制为什么可能影响特征表示。
**思路**
    这里写准备如何修改、约束或测试该机制。
```

这个部分应尽量短，优先写研究者自己的判断，而不是直接堆文献。

## Literature Review 部分

每个机制章节可以在核心假设和思路之后添加：

```markdown
#### Literature Review
```

长篇文献综述、相关论文链接、方法解释和背景材料优先放在 `Literature Review` 下，并用 `%% ... %%` 包起来：

```markdown
%% 这里放较长的文献综述、论文链接、方法背景和补充解释。 %%
```

这样可以保留参考材料，同时不打断主文档的阅读节奏。正式正文应保持精简，文献材料作为后置支撑。

## 写作风格

- 先写自己的研究假设，再写文献支撑。
- 主体内容尽量短，重点用项目符号和编号列表压缩表达。
- 机制章节优先遵循“假设 -> 思路 -> Literature Review”的顺序。
- 文献综述不要直接淹没主线，长材料优先注释保存。
- 所有新增内容应尽量贴合当前文档已有标题层级和排版方式。
