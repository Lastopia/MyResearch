# 代码设计

## 1. 当前范围

当前只做一套可手动修改的配置，以及四个严格受控的模型：

| 方法名 | 作用 |
| --- | --- |
| `rope` | RoPE 基线 |
| `alibi` | ALiBi 基线 |
| `cable` | 论文 CABLE6 公式 |
| `ra_cable` | 使用真实 attention QK 分数减弱 CABLE 距离惩罚 |

不在代码中保存硬件/模型规模预设，不保留 K-CABLE、DAPE 或 RA-CABLE 消融分支。需要改变规模时直接修改 `cfg.py`。

## 3. 唯一 CFG

`cfg.py` 中只有 `CONFIG`。默认值：

- 当前正式硬件：4 × NVIDIA L40S 48GB；每个模型使用一张卡。资源规划器自动检测空闲 GPU 与 RAM，条件允许时四个方法同时运行。效率结果必须记录实际分配 GPU，不能与其他 GPU 条件直接混合。
- 自动规划默认开启：拒绝空闲显存不足 4GB 或已有占用超过 10% 的 GPU；使用 RA-CABLE 做 forward/backward/AdamW 校准，并在 85% 空闲显存预算内选择所有任务共享的最大安全 micro-batch。
- 方法：`rope`、`alibi`、`cable`、`ra_cable`。
- seed：42。
- 主干：GPT-2 Small 级别，12 层、12 头、hidden 768、FFN 3072。
- 训练长度：1024。
- 数据：FineWeb-Edu `sample-10BT`，首轮读取固定 1B token。
- 真实评估：固定 revision 的 QASPER validation；保存 question ID、样本哈希、处理规则，并在 FineWeb 准备时检查来源 ID/URL 和精确全文哈希重叠。
- dtype：BF16。
- optimizer：AdamW；矩阵参数使用 weight decay，bias/LayerNorm/标量参数不衰减。
- 学习率：线性 warmup 到峰值，再 cosine decay 到最小学习率。
- `train.log_interval`：控制训练指标与控制台进度写入间隔。
- `train.eval_interval`：控制训练期间 held-out validation PPL 的计算间隔。
- `train.save_interval`：控制可恢复 checkpoint 的保存间隔。
- 有效 batch：每个模型相同，显存差异只通过 micro-batch 与梯度累积处理。

FineWeb-Edu 更适合当前实验，因为 CABLE 官方实验也使用 FineWeb-Edu，便于比较训练条件。OpenWebText 更适合严格复刻 GPT-2 数据路线，但不是当前 CABLE 对照的首选。

## 4. 四种位置方法

### RoPE

只旋转 Q/K，不产生 additive position bias。

### ALiBi

每个 head 使用固定 slope：

\[
b^h_{ij}=-m_h(i-j),\qquad j\le i
\]

### CABLE

与官方 CABLE6 的 GPT 路径一致：

\[
c_t^h=\operatorname{ReLU}(W_cx_t),\quad
S_i^h=\sum_{t\le i}c_t^h
\]

\[
g_i^h=\operatorname{Softplus}(W_gx_i),\quad
b^h_{ij}=-g_i^h\max(S_i^h-S_j^h,0)
\]

### RA-CABLE

直接复用 attention 已计算的内容分数：

\[
\ell^h_{ij}=\frac{q_i^h{k_j^h}^{\top}}{\sqrt d}
\]

\[
r^h_{ij}=\sigma(\operatorname{Softplus}(s_h)\ell^h_{ij}+a_h)
\]

\[
b^{h,\mathrm{RA}}_{ij}=b^{h,\mathrm{CABLE}}_{ij}(1-r^h_{ij})
\]

QK 相似度越高，\(r_{ij}\) 越大，CABLE 距离惩罚的绝对值越小。平均门控值带轻量稀疏正则，防止所有位置都被豁免。

## 5. 公平性约束

- 四个模型使用相同训练 token、顺序、token budget、有效 batch、optimizer 和学习率曲线。
- 四组完成相同的 1024 长度检索适配；评估分别读取预训练和适配后 checkpoint 并独立保存，attention 审计与 profiling 默认读取适配后 checkpoint。
- 同一 seed 下，除位置模块外的所有共享参数逐元素相同。
- CABLE 与 RA-CABLE 的基础 CABLE 层使用相同初始化；RA-CABLE 只额外增加门控参数。
- 扩展实验包含参数匹配的 `ra_cable_static`，以及从作者 Apache-2.0 官方仓库提交 `bde344a844f2bd1f498b2bac70240dcda41c50c1` 移植到当前 attention 接口的 DAPE-v1 + Kerple 强基线。
- 数据、模型和训练配置被写入 checkpoint 指纹。手改 CFG 后若旧 checkpoint 不匹配，程序会报错，不会静默复用。
- `force=True` 表示明确删除当前方法的 checkpoint、训练日志和时间账本后从零开始；代码不创建历史归档。

## 6. 断点续训与累计时间

每个 `pretrain_step*.pt` 保存：

- 模型参数；
- AdamW 参数与 moment；
- LR scheduler；
- 当前 step 与 `tokens_seen`；
- Python、NumPy、CPU/CUDA RNG；
- data epoch 与 epoch 内 batch 位置。

重新执行同一条命令且保持 `run.force=False` 时，程序自动选择编号最大的兼容 checkpoint。已完成模型直接复用 final checkpoint，未完成模型从下一步继续。

累计时间独立写入：

```text
metrics/{method}/seed42/training_time.json
metrics/{method}/seed42/adaptation_time.json
```

ledger 只显式累加每个 optimizer step 的取 batch、前向、反向、梯度裁剪、optimizer 和 scheduler 时间；模型/数据加载、日志、验证、评估与 checkpoint 写盘均不计入。checkpoint 内保存同口径时间快照。恢复时以 checkpoint 快照为基线，并把 `train.jsonl`、`validation.jsonl` 或 `adapt.jsonl` 回滚到对应 step；checkpoint 之后失败并重算的区间不会污染最终效率成本。

`run.force=True` 明确表示“删除当前方法的旧状态并从零开始”。正常断点续训不要设置 `force=True`。

## 7. 多 GPU 上的独立单卡执行

当前不是 DDP。调度器把四个完整模型作为独立单卡任务；四张 GPU 均合格且主机 RAM 足够时：

```text
GPU 0 -> RoPE       GPU 1 -> ALiBi
GPU 2 -> CABLE      GPU 3 -> RA-CABLE
```

若部分 GPU 忙碌或主机 RAM 不足，规划器会自动降低并行数并排队执行剩余方法。这样每个方法的 wall-clock、吞吐量和峰值显存都能独立记录，也不会让位置方法差异被 DDP 通信开销混淆。

## 8. 运行入口

完整流程：

```bash
python main.py run all
```

程序会自动追加写入 `output/{task}/logs/console.log`，不依赖服务器是否显示控制台。

只跑某个模型的某一步：

```bash
python main.py run train method=ra_cable
python main.py run attention_audit method=alibi
python main.py run profile method=cable
python main.py run extensions
python main.py run pilot
```

首次部署先检查环境：

```bash
python main.py run bootstrap
python main.py run resources
```

服务器路径应直接写入 `cfg.py` 的 `paths.project_root`，或设置：

```bash
export POSITION_BIAS_PROJECT_ROOT=/your/server/path/Research3
```

## 9. 测试要求

- ALiBi slope 与单调 bias 正确。
- CABLE 的累积 ReLU 距离与 query scale 公式正确。
- RA-CABLE 在同一距离下满足“高 QK 相似度 → 更小距离惩罚”。
- 四种方法的完整前向与 KV-cache 增量前向一致。
- causal mask 严格阻止未来信息。
- 各方法共享主干初始化完全一致。
- 服务器路径不依赖本地开发机目录。
- 模拟中断后的最终权重必须与不中断训练逐元素一致。
- 恢复后的 wall-clock/GPU-hours 必须包含此前 session。
