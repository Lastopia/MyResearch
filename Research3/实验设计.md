# 实验设计

## 1. 实验目标

实验围绕四个问题展开：

1. ALiBi 的不同 attention head 是否在上下文长度变化时保持近似固定的 attention distance 比例？
2. CABLE 是否打破该固定比例，但仍保留单调距离惩罚？
3. 非单调、内容相关的位置豁免是否能提高远端关键信息利用？
4. 提升是否来自正确机制，而不是更多参数、PPL 假象或随机 attention 扩散？

## 2. 对比模型

当前首轮只比较四个模型：

| 组别 | 位置方法 | 实验作用 |
| --- | --- | --- |
| RoPE | 原生 RoPE | 工业常用基线 |
| ALiBi | 固定几何 slope + 线性 bias | 固定跨头尺度、单调 bias 基线 |
| CABLE | token/head/context-dependent 累计 bias | 检验动态 head 距离是否足够 |
| RA-CABLE | CABLE + 真实 QK 相似度门控；相似度越高，距离惩罚越小 | 检验内容相关的 pairwise 距离豁免 |

独立扩展实验还包含两个对照：`ra_cable_static` 保持与 RA-CABLE 相同的门控参数量但移除 QK 内容依赖；`dape_kerple` 使用 DAPE-v1 的官方 Kerple 基线、跨 head MLP 和初始化，移植来源固定为作者 Apache-2.0 仓库提交 `bde344a844f2bd1f498b2bac70240dcda41c50c1`。

## 3. 控制变量

### 3.1 统一模型结构

主实验采用同一 GPT-2 Small 级 decoder-only Transformer：

| 参数 | 固定值 |
| --- | --- |
| 层数 | 12 |
| hidden size | 768 |
| attention heads | 12 |
| head dimension | 64 |
| FFN dimension | 3072 |
| tokenizer | GPT-2 BPE，词表固定 |
| causal mask | 相同 |
| dropout、激活函数、LayerNorm | 相同 |
| 训练上下文长度 | 1024 |

所有组共享完全相同的 Transformer 主干。唯一主动变化是位置编码模块。CABLE 和 RA-CABLE 的额外参数单独报告。

seed 固定为 42。各组共享同一份主干初始化权重、相同数据顺序和相同 batch 划分；CABLE 与 RA-CABLE 的基础 CABLE 参数也使用相同初始化。

### 3.2 统一训练数据

- 预训练数据：FineWeb-Edu `sample-10BT` 的确定性流式子集；首轮固定使用 1B token。
- validation/test：从训练文档之外按 document ID 固定划分，禁止相同文档跨 split。
- tokenizer、清洗、去重、拼接和 EOS 规则完全一致。
- 保存数据版本、处理脚本版本、split ID 与哈希。
- 所有模型看到完全相同数量、顺序和位置的训练 token。

为保证小模型能理解检索任务格式，预训练完成后，对所有组进行相同的短上下文关联检索适配：

- 适配任务：key-value retrieval 与 multi-query associative recall。
- 适配最大长度：1024，不提供任何超出预训练长度的训练样本。
- 适配数据、step、学习率、batch、seed 和候选答案集合完全相同。
- 长度 2048–8192 的样本只用于测试。
- PPL、真实问答和合成检索分别在预训练与适配后 checkpoint 上运行并以 `checkpoint_kind` 分表；attention 审计和性能 profiling 默认使用适配后 checkpoint。这样可以区分位置机制的预训练收益与合成检索适配收益。

### 3.3 统一训练设置

| 参数 | 固定设置 |
| --- | --- |
| token budget | 每组 1B |
| effective batch | 65,536 tokens/step |
| optimizer | AdamW |
| \(\beta_1,\beta_2\) | 0.9, 0.95 |
| weight decay | 0.1 |
| peak learning rate | \(6\times10^{-4}\) |
| schedule | 1% warmup + cosine decay |
| gradient clipping | 1.0 |
| dtype | BF16 |
| seed | 42 |
| checkpoint | 按固定 token 数保存，不用验证集提前停止 |

训练期间每隔 `train.eval_interval` 个 optimizer step 在固定 held-out validation 子集上计算 loss/PPL；`log_interval` 与 `save_interval` 分别控制日志和可恢复 checkpoint。所有间隔对四个方法完全相同。

若服务器任务中断，恢复模型、optimizer、scheduler、RNG、数据 batch 位置和 checkpoint 对应的有效训练时间。时间账本只累计 optimizer step 内的取 batch、前向、反向、梯度裁剪、optimizer 与 scheduler 时间；验证、评估、日志和 checkpoint 写盘不计入。恢复时日志与时间同时回滚到 checkpoint，失败后重算区间不进入最终效率成本。

如果显存不同，只允许使用 gradient accumulation 调整 micro-batch；effective batch、token budget 和优化器更新次数不变。

## 4. 评估数据与长度

统一评估长度：

\[
L\in\{1024,2048,4096,8192\}
\]

其中 1024 是训练长度，2048–8192 是长度外推范围。完整 attention 审计和性能 profiling 首轮只到 4096，避免在 L40S 48GB 上保存 8192 的 \(O(L^2)\) 中间矩阵。

评估数据分为四类，必须分表报告：

1. **自然语言建模**：FineWeb-Edu held-out 与 WikiText-103，只评估，不参与训练。
2. **真实长文档问答**：固定 revision 的 QASPER validation。问题、答案、论文正文和证据均来自公开人工标注数据；每个长度截取包含标注证据的连续真实论文窗口，把问题放在末尾，并保存 paper/question ID、处理规则和 SHA-256。
3. **受控远程检索（synthetic）**：远端目标 key、近端强干扰 key、位置匹配的无关 key；目标位置均匀覆盖开头、中间和结尾。
4. **关联回忆（synthetic）**：单 key-value、multi-query associative recall，以及共享前缀、仅成员 token 不同的相似 key 干扰条件。

QASPER 与合成任务不得混合平均。FineWeb 文档进入任何 train/valid/test split 前，会同时执行来源 ID、规范化全文 SHA-256，以及对 QASPER 论文和 WikiText-103 test 的 13-token shingle 近重复检查；命中文档直接从 FineWeb 语料排除。若扫描未覆盖全部已准备 FineWeb 文档，QASPER 评估直接阻止运行。

合成长样本在不同长度保持相同目标关联，并分别把目标放在开头、中间和结尾区域，避免把单一目标位置误当作长度效应。RoPE 同时报告原生外推和按 \(L/1024\) 缩放位置索引的线性 RoPE-PI 对照。

## 5. 实验流程

### Stage A：训练与基础检查

1. 使用相同主干初始化、数据顺序和训练配置训练四个模型。
2. 检查 loss、gradient norm、NaN/Inf、吞吐量和显存。
3. 在 1024 内验证模型均正常收敛；不根据测试长度结果调参。

### Stage B：Attention distance 审计

这是验证 ALiBi 固定 head 比例现象的核心流程。

1. 从固定测试集选择配对的自然文本、同 token 多重集的内容打乱文本和合成远端目标控制，长度为 1024、2048、4096。
2. 对每层、每头保存：
   - 原始 content logit \(QK^\top/\sqrt d\)；
   - additive positional bias（适用于 ALiBi、CABLE、RA-CABLE）；
   - softmax 后最终 attention。
3. RoPE 没有独立 additive bias，只比较最终 attention；不得伪造与加性模型等价的 bias。
4. 为减少因果 mask 边界影响，主统计只使用序列最后 25% 的 query；同时把全序列结果放入附录。
5. 分别在自然文本、内容打乱文本、远端目标文本上计算 attention distance，区分长度适应和内容适应。
6. 将 head distance 指标与同一样本上的检索正确率、相关 token attention mass 做配对分析。

### Stage C：单调性与远端重要 token

1. 对每个 query 同时放置：
   - 一个远端相关 key；
   - 一个近端语义相似但错误的 key；
   - 若干距离匹配的无关 key。
2. 改变目标距离但保持目标内容与候选集合不变。
3. 比较 positional bias、content logit 和最终 attention，判断失败来自内容识别还是距离惩罚。
4. 交换目标与干扰项的位置，检查预测是否跟随内容而不是固定位置。

### Stage D：长度外推与效率

1. 在所有长度上评估 PPL、检索和关联回忆。
2. 记录性能、错误豁免、attention sink、训练/推理时间、VRAM 和主机 RAM。
3. 当前不运行 K-CABLE、DAPE 或 RA-CABLE 消融；只有四模型 pilot 明确后再决定是否扩展。

## 6. 评估指标

### 6.1 语言模型质量

#### Perplexity（PPL，越低越好）

\[
\mathrm{PPL}=\exp\left(
-\frac1N\sum_{t=1}^{N}\log p(x_t|x_{<t})
\right)
\]

- 用途：衡量整体 next-token prediction 质量。
- 低：模型对真实 token 分配更高概率。
- 高：语言建模质量较差或长度外推失稳。
- 注意：长上下文 PPL 低不等于模型真正使用远程信息，因此 PPL 只作为基础指标，不能单独支持本文结论。

#### Short-context PPL Change（绝对值越低越好）

\[
\Delta\mathrm{PPL}_{short}
=
\frac{\mathrm{PPL}_{method}-\mathrm{PPL}_{CABLE}}
{\mathrm{PPL}_{CABLE}}
\]

- 用途：检查长程改进是否牺牲 512/1024 长度内质量。
- 接近 0：与 CABLE 基线相当。
- 明显为正：方法损害短上下文质量。
- 为负：方法同时改善短上下文质量。

### 6.2 Attention distance 与跨头比例

令 \(A_{l,h,i,j}\) 为第 \(l\) 层第 \(h\) 个头从 query \(i\) 到 key \(j\) 的 attention。

#### Mean Attention Distance（MAD）

\[
\mathrm{MAD}_{l,h}(L)
=
\mathbb E_i
\left[
\sum_{j\le i}A_{l,h,i,j}(i-j)
\right]
\]

- 用途：衡量一个 head 平均关注多远。
- 高：该头更偏向远距离信息。
- 低：该头更局部。
- MAD 本身没有“越高越好”；必须结合任务和相关 token 指标解释。

#### Normalized Attention Distance（NAD）

\[
\mathrm{NAD}_{l,h}(L)
=
\mathbb E_i
\left[
\sum_{j\le i}A_{l,h,i,j}
\frac{i-j}{\max(i,1)}
\right]
\]

- 用途：消除上下文长度量纲，使 1024 与 8192 可以比较。
- 高：在可用上下文中使用较大的相对距离。
- 低：相对感受野随长度增长而收缩。

#### Attention Radius \(R_{90}\)（越高表示感受野越宽）

\[
R_{90}
=
\min\left\{
r:
\sum_{i-j\le r}A_{i,j}\ge0.9
\right\}
\]

- 用途：得到包含 90% attention mass 的最小距离范围。
- 高：attention 分布更宽。
- 低：更接近局部窗口。
- 该指标同样不直接代表质量。

#### Geometric Head Fit（GHF，\(R^2\) 越高表示越接近固定几何模式）

对每层拟合：

\[
\log(\mathrm{MAD}_{l,h}+\epsilon)=a_l+b_l h
\]

以拟合 \(R^2\) 作为 GHF。

- 用途：验证各头 attention distance 是否接近几何级数。
- 高：head distance 更符合固定等比排列，预计 ALiBi 较高。
- 低：各头距离关系更自由。
- 低 GHF 不自动代表更好，只代表不再遵循简单几何模板。

#### Relative Head Distance Drift（RHDD，越高表示比例越会随长度改变）

先定义 head distance share：

\[
p_{l,h}(L)
=
\frac{\mathrm{MAD}_{l,h}(L)}
{\sum_{h'}\mathrm{MAD}_{l,h'}(L)}
\]

再计算各长度下 \(p_{l,h}(L)\) 的平均变异系数。

- 用途：直接检验“各头相对比例是否固定”。
- 低：不同长度下各头保持近似相同比例，模式较刚性。
- 高：模型会随长度重新分配不同 head 的距离范围。
- 必须结合检索性能；过高也可能只是 attention 不稳定。

#### Context Adaptivity Score（CAS，越高表示更依赖输入内容）

对同长度不同样本的 head distance share 计算平均 Jensen-Shannon divergence：

\[
\mathrm{CAS}
=
\mathbb E_x
\left[
\operatorname{JSD}(p(x)\,\|\,\bar p)
\right]
\]

- 用途：衡量 head 距离模式是否随内容而变化。
- 低：不同输入产生几乎相同的 head 比例。
- 高：模型按输入改变局部/全局 head 分工。
- 高 CAS 只有在提高相关 token 利用时才是正面结果。

### 6.3 单调性与语义豁免

#### Bias Monotonic Violation Rate（BMVR）

\[
\mathrm{BMVR}
=
P\left(
b_{i,j_{far}}>b_{i,j_{near}},
\ j_{far}<j_{near}<i
\right)
\]

- 用途：检查位置 bias 是否允许远 key 获得比近 key 更有利的位置修正。
- 0：严格单调；ALiBi/CABLE 理论上应接近 0。
- 较高：存在非单调 bias。
- 不是越高越好；随机、无关的 violation 也是失败。

#### Relevant Attention Advantage（RAA，越高越好）

\[
\mathrm{RAA}
=
A(i,j_{relevant})
-
\frac1K\sum_{k=1}^{K}A(i,j_{distractor,k})
\]

- 用途：衡量远端相关 token 相对匹配干扰项获得的 attention 优势。
- 高：attention 更忠实于语义相关性。
- 低于 0：干扰项得到的 attention 高于正确 token。

#### Semantic Exemption Success Rate（SESR，越高越好）

\[
\mathrm{SESR}
=
P\left(
b_{i,j_{relevant,far}}
>
b_{i,j_{irrelevant,near}}
\right)
\]

- 用途：检查非单调 bias 是否准确授予远端相关 token，而不只是整体减弱距离惩罚。
- 高：正确目标经常获得位置豁免。
- 低：模型仍主要服从距离。

#### False Exemption Rate（FER，越低越好）

\[
\mathrm{FER}
=
P(r_{ij}>\delta\mid j\text{ 是远端无关 token})
\]

- 用途：检查 gate 是否把豁免错误地给无关 token。
- 低：豁免稀疏且有选择性。
- 高：可能出现 attention 扩散或 attention sink。

### 6.4 远程任务性能

#### Retrieval Accuracy / Exact Match（越高越好）

- 用途：目标 key-value 是否被正确取回。
- 高：模型能实际使用远程相关信息。
- 低：模型未识别目标，或目标被距离偏置/干扰项压制。
- 分别报告每个长度、每个目标位置区间，不能只报告总平均。

#### Distance-conditioned Accuracy（曲线越平越好）

按目标与 query 的相对距离分桶报告 accuracy。

- 用途：观察性能是否随距离增长而系统下降。
- 高且平坦：远近目标均能可靠访问。
- 近距离高、远距离低：存在距离相关退化。

#### Length Degradation Rate（LDR，越低越好）

\[
\mathrm{LDR}
=
-\operatorname{slope}
\left(
\mathrm{Accuracy}(L)
\text{ 对 }
\log_2L
\right)
\]

- 用途：用一个数概括准确率随长度增长的下降速度。
- 接近 0：长度增长几乎不损害任务表现。
- 高：上下文越长，性能下降越快。
- 若为负，表示准确率随长度增加而上升，需要检查数据或任务难度是否一致。

#### Relevant-context Utilization Gain（RCUG，越高越好）

\[
\mathrm{RCUG}
=
\mathrm{NLL}_{remove\ relevant}
-
\mathrm{NLL}_{full}
\]

- 用途：移除远端相关 span 后，正确答案 NLL 是否恶化。
- 高：模型确实使用了该远端信息。
- 接近 0：即使 attention 可视化看起来关注远端，预测并不依赖它。

### 6.5 稳定性与效率

效率测试统一使用相同 GPU、CPU、主机 RAM、PyTorch/CUDA 版本、attention kernel、dtype 和 batch。每种配置先预热 20 次，再测量 100 次；计时前后进行 GPU synchronization，报告 median 与 P95。推理统一启用 KV cache，并分别测量 prefill 和 decode，不能只报告合并吞吐量。

#### Attention Sink Ratio（越低越好）

统计 BOS、换行、分隔符或单个 token 获得超过阈值 attention mass 的比例。

- 高：少数 token 吸收大量注意力，可能是错误豁免或退化。
- 低：没有明显的非语义集中。

#### Training/Inference Throughput（越高越好）

- 单位：tokens/s。
- 用途：衡量动态 bias 和 pairwise gate 的运行成本。
- 高：效率好；低：方法额外计算较重。
- 在相同硬件、dtype、batch 和序列长度下测量。

#### Training Step Time（越低越好）

- 单位：ms/optimizer step。
- 用途：比较相同 effective batch 和序列长度下，每次参数更新需要的时间；测量包含全部 gradient accumulation、梯度裁剪、正式 AdamW 参数组、optimizer 与 scheduler step。
- 低：单步训练更快。
- 高：位置编码或 relevance gate 带来更大训练开销。
- 首轮在 1024、2048、4096 长度下测量；若用 gradient accumulation，必须包含全部 micro-step 时间。

#### Total Training Cost（越低越好）

- 同时报告 wall-clock hours 和 GPU-hours：

\[
\mathrm{GPUHours}
=
\mathrm{WallClockHours}\times\mathrm{GPUCount}
\]

- 用途：衡量完成相同固定 token budget 的实际总时间成本。
- 低：完成同等训练数据所需计算时间更少。
- 高：方法整体训练成本更大。
- 所有组使用相同 GPU 数量；若因故不同，主要比较 GPU-hours，并同时保留 wall-clock time。

#### Prefill Latency / Time to First Token（越低越好）

- 单位：ms 或 s/request。
- 用途：测量模型读取完整上下文并产生第一个输出 token 的时间。
- 低：长提示的首 token 响应更快。
- 高：动态位置 bias 在长上下文预处理阶段成本更大。
- 在 batch size 1、相同输入长度和相同 KV cache 设置下，分别报告各评估长度。

#### Decode Latency（越低越好）

- 单位：ms/generated token，同时报告 decode tokens/s。
- 用途：测量 KV cache 已建立后逐 token 生成的时间。
- 低：生成阶段更快。
- 高：每个新增 token 的动态 bias 或 gate 计算成本更大。
- 使用固定 256-token 输出长度，报告 median 和 P95。

#### Peak VRAM（越低越好）

- 单位：GB。
- 用途：衡量训练、prefill 和 decode 三个阶段的 GPU 显存成本。
- 低：可支持更大的 batch 或上下文长度。
- 高：部署和训练显存成本更大，可能更早发生 OOM。
- 三个阶段分别报告，不使用进程结束后的剩余显存代替峰值。

#### Peak Host RAM（越低越好）

- 单位：GB。
- 用途：衡量数据加载、动态 bias 构造、缓存和评估过程的主机内存成本。
- 低：CPU 侧内存需求较小。
- 高：可能限制并行 worker 数量或造成系统换页，进而放大时间成本。
- 报告进程 RSS 峰值；数据集文件缓存不计入模型进程内存。

#### Added Parameters（越低越好）

- 同时报告绝对数量和相对主干比例。
- 用途：排除性能提升只是来自大量新增容量。

## 7. 统计分析

- 正式配置固定使用 seed 42–49 的 8 个配对重复；数据顺序仍由独立的固定 data seed 2025 控制。确认性检验只覆盖短上下文 PPL、4096 QASPER Token F1 和 8192 适配后远程检索三个主终点，并进行 Holm 校正；少于 8 个完整配对 seed 时不输出推断结果。
- 检索任务仍使用完全相同的样本与目标位置做配对比较。
- attention 指标按 layer、head、length 保存原始值，再给出 early/middle/late layer 聚合。
- bootstrap 区间只能描述当前评估样本的不确定性，不能替代多 seed 训练重复。

## 8. 成功判定

RA-CABLE 只有同时满足以下条件，才能支持理论假设：

1. 在 2048–8192 的远程检索和关联回忆上优于 CABLE，并在后续多 seed 实验中复核。
2. 1024 的 PPL 相对 CABLE 恶化不超过 1%。
3. RAA、SESR 提高，同时 FER 和 attention sink ratio 没有明显恶化。
4. RHDD/CAS 表明 head distance 会按长度或内容调整，并且这种调整与任务提升相关。
5. 相对 CABLE 的总 GPU-hours、训练单步时间、prefill/decode 延迟、峰值 VRAM 和峰值主机 RAM 增幅均需报告；建议主要时间与显存开销增幅不超过 10%。

以下结果不能单独视为成功：

- 只有 PPL 更低；
- 只有 BMVR 更高；
- 只有平均 attention distance 更大；
- attention 图更分散，但检索、RCUG 和错误豁免没有改善。

## 10. 当前实施配置

- 单一配置文件：`cfg.py`，不使用规模预设。
- 当前正式硬件：4 × NVIDIA L40S 48GB；资源规划器自动选择合格 GPU，四张卡均空闲且 RAM 足够时四个单卡模型任务同时运行。所有效率表必须同时保存 GPU 型号、PyTorch/CUDA、attention kernel、dtype、batch 和梯度累积条件。
- 模型：GPT-2 Small 级别，约 124M。
- 方法：RoPE、ALiBi、CABLE、RA-CABLE。
- seed：42。
- 数据：FineWeb-Edu `sample-10BT`，首轮 1B 训练 token。
- 真实长文档评估：QASPER validation 固定 64 个样本；FineWeb 中与评估目标精确或近重复的文档在数据准备阶段直接排除。
- PPL 每个长度和语料固定 50 个 batch；合成检索每个长度固定 512 个样本；attention 审计每个长度固定 16 个配对样本。所有方法和 seed 复用相同输入哈希。
- 512 个二项检索样本在最保守的 50% 准确率附近对应约 ±4.3% 的 95% 正态近似误差界；QASPER 使用当前固定 revision 中满足长度、人工答案和证据约束的 64 个样本。最终不把样本内重复当作训练 seed，推断单位始终是 8 个独立训练 seed。
- Profiling：预热 20 次、测量 100 次、decode 256 token；训练 step 使用完整 65,536-token effective batch 和全部梯度累积。
- 学习率：线性 warmup 后 cosine decay。
- 若 pilot 结果值得继续，再手动修改同一 CFG 扩展训练预算、长度或 seed；当前代码不保存额外预设。
