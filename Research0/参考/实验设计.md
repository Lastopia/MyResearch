# 实验设计

## 基础设定

### 位置编码

本轮实验默认使用 `RoPE` 作为位置编码方式，暂时不再把位置编码作为主要实验变量。原因是上一轮实验已经围绕位置编码做过比较，而本轮研究重点转向 Transformer 内部的 `Attention`、`FFN` 和 `loss` 等机制修改；在这种情况下，固定一个性能稳定、应用广泛的位置编码方式，有助于减少无关变量，让后续实验结果更容易归因。

### 数据集

本轮实验默认使用 `OpenWebText` 作为主要数据集。这里使用的是 OpenWebText，而不是 OpenAI 原始 WebText；OpenWebText 可以视为 GPT-2 WebText 风格语料的开源复现，更适合作为本项目可获取、可复现的训练数据来源。

第一阶段可以先使用 OpenWebText 的较小子集配合 `test` 小模型快速筛选机制变体；第二阶段再扩大数据量，并使用 `gpt2_small` 级别模型复验较有希望的机制改动。这样既能保持数据分布接近 GPT-2 风格，又能避免一开始就承担过高训练成本。

命名时统一使用 `OWT` 作为 `OpenWebText` 的简写。
实际 HuggingFace 数据集 id 使用 `Skylion007/openwebtext`，不要使用裸名 `openwebtext`。

`data` 配置建议保留以下字段：

```python
data = {
    "corpus": "OWT",
    "raw_alias": "OWT",
    "tokenizer_alias": "gpt2",
    "tokenized_alias": "OWT_gpt2",
    "blocks_alias": "OWT_gpt2_b256",
    "block_size": 256,
    "train_blocks": 20000,
    "valid_blocks": 2000,
    "seed": 42,
}
```

其中 `seed` 是数据 seed，专门控制数据采样、shuffle 和 train/valid block 切分。它应独立于全局 `run.seed`，不强制一起切换。这样可以在比较不同模型机制时固定同一批数据，也可以在需要时单独改变数据切分，区分“模型初始化随机性”和“数据采样随机性”的影响。

第一阶段 `test` 小模型筛选默认使用：

```text
block_size = 256
train_blocks = 20000
valid_blocks = 2000
```

约对应 `5.12M` train tokens 和 `0.512M` valid tokens。

第二阶段 `gpt2_small` 复验默认使用：

```text
block_size = 512
train_blocks = 100000
valid_blocks = 5000
```

约对应 `51.2M` train tokens 和 `2.56M` valid tokens。

### SAE hook point

SAE 默认分析最后一层 block 输出后的 residual stream。配置中使用：

```python
sae = {
    "hook_layer": -1,
}
```

其中 `-1` 表示自动取当前模型的最后一层，例如 `test` 模型的第 6 层，或 `gpt2_small` 模型的第 12 层。这样可以让 SAE 主要分析模型最终形成、最接近 next-token prediction 的语义表示，同时避免切换模型规模时忘记手动修改 hook 层数。

## Stage 0：统一控制变量

本轮实验的核心目标是比较不同机制是否能诱导模型形成更适合 SAE 解析的内部表示。因此所有实验必须严格控制无关变量，避免把数据、模型规模、训练步数或 SAE 设置的差异误判为机制差异。

### 固定变量

| 类别 | 固定内容 | 目的 |
|---|---|---|
| 数据集 | `Skylion007/openwebtext` / `OWT` | 保持语言分布一致，避免数据差异影响 SAE feature |
| tokenizer | GPT-2 tokenizer | 保持 token 边界一致 |
| 位置编码 | `RoPE` | 上一轮已比较位置编码，本轮不再让位置编码成为变量 |
| block size | Stage 1 使用 256，Stage 2 使用 512 | 同一 stage 内必须一致 |
| train / valid split | 固定 `data.seed = 42` | 保证不同模型看到完全相同的数据块 |
| 模型规模 | 同一 stage 内固定层数、宽度、head 数、FFN hidden size 或 active parameter count | 避免容量差异造成误判 |
| optimizer | AdamW、学习率、warmup、batch size、weight decay、gradient clipping 全部一致 | 保证训练动力学可比 |
| training tokens | 同一 stage 内完全一致 | 避免训练更久导致 SAE 更好 |
| random seed | 第一轮固定一个 seed，关键结果再补 3 seeds | 先省成本，再验证稳健性 |
| SAE hook point | 最后一层 block 输出后的 residual stream，`hook_layer = -1` | 统一分析最终语义表示 |
| SAE architecture | expansion factor、L1 / TopK、训练步数、学习率、训练 tokens 完全一致 | 保证 SAE 指标可比 |

### 模型结构基线

Baseline 使用 decoder-only causal Transformer：

```text
token embedding
+ RoPE causal self-attention
+ residual connection
+ FFN / MLP
+ residual connection
+ final norm
+ LM head
```

建议使用两档规模：

| Stage | 模型 | 用途 |
|---|---|---|
| Stage 1 | `test` 小模型，例如 6 layers | 快速筛选机制，降低试错成本 |
| Stage 2 | `gpt2_small` 级别，例如 12 layers | 对 Stage 1 胜出的机制做复验 |

同一 stage 内，所有实验组必须保持：

```text
n_layer, n_head, d_model, block_size, tokenizer, training tokens
```

尽量一致。对于 FFN 变体，如果结构改变导致参数量变化，需要优先匹配 active parameter count；如果无法完全匹配，必须记录：

```text
total_params
active_params_per_token
FLOPs_per_token
```

作为结果解释时的控制项。

## Stage 1：最小机制筛选

Stage 1 使用 `test` 小模型和 OWT 小子集，目标是用最低成本筛出最有希望提升 SAE 可解析性的机制。

### Stage 1 数据设置

```text
dataset = Skylion007/openwebtext
tokenizer = gpt2
block_size = 256
train_blocks = 20000
valid_blocks = 2000
train_tokens = 5.12M
valid_tokens = 0.512M
data.seed = 42
```

这样设计的理由：

1. OWT 接近 GPT-2 WebText 风格，适合训练小型 causal LM。
2. 数据公开可复现，不依赖封闭语料。
3. 5M tokens 级别足够让小模型学到初步语言结构，也足够低成本地比较机制趋势。
4. 固定 block 切分可以保证每个实验组看到完全相同的 token 序列。

### Stage 1 实验组

| 组别  | 实验组                             | 只改变什么                                             | 不改变什么                 |
| --- | ------------------------------- | ------------------------------------------------- | --------------------- |
| B0  | Standard Transformer            | 不做机制修改                                            | 数据、模型规模、训练、SAE 全部作为参照 |
| A1  | Top-K Attention                 | attention mask 从 dense softmax 改为 per-query Top-K | FFN、loss、参数规模尽量不变     |
| F1  | Grouped FFN with Limited Mixing | FFN 改为 grouped + small mixing branch              | attention、loss 不变     |
| F2  | Sparse FFN                      | FFN hidden activation 改为 Top-K 或 threshold sparse | attention、loss 不变     |
| L1  | LM + L1 Activation Sparsity     | loss 增加 FFN activation L1 penalty                 | architecture 不变       |

### A1：Top-K Attention 控制方式

标准 attention：

$$
S=\frac{QK^\top}{\sqrt{d_k}},\quad A=\mathrm{softmax}(S),\quad O=AV
$$

Top-K attention：

$$
I_i=\mathrm{TopK}_j(S_{ij}, k)
$$

$$
a_{ij}^{topk}=
\begin{cases}
\dfrac{\exp(S_{ij})}{\sum_{m\in I_i}\exp(S_{im})}, & j\in I_i\\
0, & j\notin I_i
\end{cases}
$$

控制变量要求：

- 只改 attention 的 support，不改 $Q,K,V,O$ projection 维度。
- head 数、层数、hidden size 不变。
- causal mask 仍然保留，Top-K 只能在历史 token 内选择。
- 第一轮建议固定 `k = 32` 或 `k = block_size / 8`，不要同时扫多个 k，避免实验组膨胀。
- 记录每层每头实际 attention support size 和 attention entropy。

该组回答：

> content-based sparse routing 是否能减少 residual stream 的来源混合，从而提升 SAE feature quality？

### F1：Grouped FFN with Limited Mixing 控制方式

标准 FFN：

$$
\mathrm{FFN}(x)=W_2\sigma(W_1x+b_1)+b_2
$$

Grouped + limited mixing：

$$
\mathrm{FFN}_{group+mix}(x)
=
\mathrm{FFN}_{block}(x)
+
\alpha \mathrm{FFN}_{mix}(x)
$$

其中：

$$
\mathrm{FFN}_{block}(x)=W_2^{block}\sigma(W_1^{block}x)
$$

控制变量要求：

- group 数第一轮固定，例如 `G = 4`。
- mixing branch 使用较小宽度，例如 baseline FFN hidden size 的 `10%-25%`。
- 尽量让 active parameter count 接近 baseline FFN。
- 不额外加入 sparsity loss。
- attention 完全保持 baseline。

该组回答：

> 人为加入 FFN 模块边界，是否能让 SAE 分解出更少纠缠、更少重复的 feature subspace？

### F2：Sparse FFN 控制方式

标准 FFN hidden activation：

$$
h=\sigma(W_1x+b_1)
$$

Sparse FFN：

$$
I=\mathrm{TopK}_m(h_m,k_{ffn})
$$

$$
\tilde{h}_m=
\begin{cases}
h_m, & m\in I\\
0, & m\notin I
\end{cases}
$$

$$
y=W_2\tilde{h}+b_2
$$

控制变量要求：

- 第一轮建议使用固定 activation Top-K，不同时测试多个阈值方案。
- `k_ffn` 设为 FFN hidden size 的固定比例，例如 `25%` 或 `50%`，先避免过强稀疏。
- 不加入 L1 loss，否则会和 L1 loss 实验组混淆。
- attention 和 optimizer 保持 baseline。
- 记录 FFN activation L0、activation frequency、dead unit rate。

该组回答：

> 原模型内部 FFN 激活更稀疏，是否会让 SAE 更容易恢复单义特征？

### L1：LM + L1 Activation Sparsity 控制方式

标准 LM loss：

$$
L_{LM}=-\sum_t\log p(x_t|x_{<t})
$$

加入 FFN activation sparsity：

$$
L=L_{LM}+\lambda L_{sparse}
$$

$$
L_{sparse}=\frac{1}{LBT}\sum_{l,b,t}\|h_{b,t}^{l}\|_1
$$

控制变量要求：

- architecture 完全保持 baseline。
- 第一轮只选一个较小 $\lambda$，例如让训练初期 sparsity loss 占 LM loss 的小比例，避免 LM 直接崩。
- L1 作用点优先选择 FFN hidden activation，而不是 residual stream。
- 记录原始 LM loss 和 total loss，报告时主要比较 validation LM loss。

该组回答：

> 训练目标中的稀疏压力是否能比单纯结构修改更直接地改善 SAE feature quality？

## Stage 2：扩大规模复验

Stage 2 不再跑全部机制。只选择 Stage 1 中最有希望的 1-2 个机制，加 baseline 复验。

进入 Stage 2 的建议标准：

| 条件 | 说明 |
|---|---|
| validation loss 没有明显崩坏 | 相比 baseline 不应大幅变差 |
| SAE reconstruction loss 不升高或略有下降 | 说明 SAE 没有更难重构 |
| 同等 L0 下 interpretability 指标更好 | 说明不是单纯稀疏，而是更可解释 |
| feature duplication / polysemanticity 降低 | 说明 feature quality 真实改善 |
| ablation effect 更局部 | 说明 feature 更接近可干预单元 |

### Stage 2 数据设置

```text
dataset = Skylion007/openwebtext
tokenizer = gpt2
block_size = 512
train_blocks = 100000
valid_blocks = 5000
train_tokens = 51.2M
valid_tokens = 2.56M
data.seed = 42
```

Stage 2 的目的不是探索，而是确认 Stage 1 结果是否在更大模型和更多 tokens 下仍然成立。

建议实验组：

```text
B0 baseline
W1 winner mechanism from Stage 1
W2 optional second winner if budget allows
```

如果 Stage 1 中 Top-K Attention 胜出，可以在 Stage 2 加一个 Entmax 作为额外对照：

```text
B0 baseline
A1 Top-K Attention
A2 Entmax Attention
```

这时 Entmax 的作用是判断：提升来自一般 sparse routing，还是 hard Top-K selection。

## Stage 3：SAE 训练与评估

每个训练好的 LM 都必须用完全相同的 SAE 设置分析，否则 SAE 差异无法归因到原模型机制。

### SAE 数据控制

SAE training tokens 必须来自同一批 OWT token block，且不同模型使用完全相同的 token positions 抽取 activation。

建议：

```text
sae_train_tokens = fixed subset from train split
sae_valid_tokens = fixed subset from valid split
hook_layer = -1
hook_point = final residual stream after last block
```

如果资源允许，额外保存：

```text
mlp_out_last_layer
attn_out_last_layer
```

但第一阶段主指标仍以 final residual stream SAE 为准。

### SAE 指标

| 指标 | 代表什么 | 有什么用 |
|---|---|---|
| reconstruction loss | SAE 重构 activation 的误差 | 判断该模型表示是否容易被稀疏字典重构 |
| loss recovered | 用 SAE reconstruction 替换原 activation 后恢复多少 LM 性能 | 比单纯 MSE 更接近模型功能保真度 |
| L0 | 平均每个 token 激活多少 SAE feature | 衡量 SAE code 稀疏程度 |
| L1 | feature activation 总强度 | 辅助判断稀疏性和激活规模 |
| dead feature rate | 几乎从不激活的 SAE feature 比例 | 判断 SAE 容量是否浪费 |
| activation frequency | 每个 feature 被激活的频率分布 | 判断是否有少数 feature 过度承担功能 |
| feature interpretability score | feature 是否能被稳定解释 | 核心 monosemanticity 指标 |
| polysemanticity score | 单个 feature 是否对应多个无关概念 | 直接衡量单义性失败 |
| feature duplication | 多个 feature 是否解释同一概念 | 判断是否存在冗余拆分 |
| ablation effect | 删除某个 feature 对输出的影响 | 判断 feature 是否是功能性特征，而不是相关但无用 |
| intervention locality | feature ablation 是否只影响相关 token / 行为 | 判断 feature 是否可控、低副作用 |

### SAE 评估原则

不能只看 reconstruction loss。一个模型可能更容易重构，但 feature 更混乱；也可能 L0 更低，但 LM 功能损失更大。因此需要同时报告：

$$
\text{SAE Fidelity}=(\text{reconstruction loss},\ \text{loss recovered})
$$

$$
\text{SAE Sparsity}=(L0,\ L1,\ \text{dead feature rate})
$$

$$
\text{SAE Interpretability}=(\text{interpretability score},\ \text{polysemanticity},\ \text{duplication})
$$

$$
\text{SAE Causality}=(\text{ablation effect},\ \text{intervention locality})
$$

最终比较时应使用 trade-off 视角：

$$
\Delta L_{LM}=L_{LM}^{variant}-L_{LM}^{baseline}
$$

$$
\Delta S_{SAE}=S_{SAE}^{variant}-S_{SAE}^{baseline}
$$

重点看：

$$
\frac{\Delta S_{SAE}}{\Delta L_{LM}}
$$

也就是每付出一点 LM 性能代价，换来多少 SAE 可解析性提升。

## Stage 4：机制专项指标

除了 SAE 指标，每个机制还需要记录自己的内部指标。否则即使 SAE 变好，也不知道机制是否真的按预期工作。

### Attention 机制指标

| 指标 | 代表什么 | 对 Top-K 的意义 |
|---|---|---|
| attention entropy | attention 分布是否集中 | Top-K 应显著降低 entropy |
| support size | 每个 query 实际关注多少 token | 确认 routing sparsity |
| top-k stability | 不同 batch / checkpoint 下选中的 key 是否稳定 | 判断是否形成稳定信息路径 |
| attention path overlap | 不同 head 是否选择相似路径 | 判断 head redundancy |
| path ablation effect | 删除 top-k path 对输出影响 | 判断被选路径是否真有功能 |

### FFN 机制指标

| 指标 | 代表什么 | 对 FFN 组的意义 |
|---|---|---|
| FFN activation L0 | 每个 token 激活多少 hidden units | 检查 Sparse FFN 是否真的稀疏 |
| activation frequency | hidden unit 使用频率 | 判断是否有 dead / overused units |
| group utilization | 不同 group 被使用的程度 | 检查 Grouped FFN 是否负载均衡 |
| cross-group covariance | group 之间表示是否纠缠 | 判断 grouped structure 是否真的降低 subspace overlap |
| group ablation effect | 删除某个 group 的行为影响 | 判断 group 是否形成可解释模块 |

### Loss 机制指标

| 指标 | 代表什么 | 对 L1 组的意义 |
|---|---|---|
| L1 penalty magnitude | 稀疏项强度 | 确认 loss 没有过强或过弱 |
| LM loss gap | 稀疏正则带来的性能代价 | 判断机制是否可接受 |
| activation norm | hidden activation 是否被整体压小 | 防止模型只是缩放激活逃避 L1 |
| effective sparsity | 激活接近 0 的比例 | 判断 L1 是否真的改变表示结构 |

## Stage 5：结果判定规则

一个机制只有同时满足以下条件，才认为值得进入下一阶段：

1. validation LM loss 代价可接受；
2. SAE reconstruction / loss recovered 不变差；
3. SAE feature interpretability 提升；
4. polysemanticity 或 duplication 至少一个下降；
5. ablation / intervention 更局部；
6. 机制专项指标证明该机制确实发生了预期变化，例如 Top-K 降低 path entropy、Sparse FFN 降低 activation L0。

如果结果冲突，按以下优先级判断：

```text
LM 不崩
> SAE fidelity 可接受
> feature interpretability 提升
> ablation effect 更局部
> 机制指标符合预期
```

也就是说，可解释性提升不能建立在模型基本语言能力崩坏的基础上。我们要找的是“更可解析的有效表示”，不是“更稀疏但更笨的模型”。
