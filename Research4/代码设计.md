# FFN Concept Subspace Bus V2：代码设计

## 1. 总览

| 原则 | 落地方式 |
|---|---|
| 单一配置入口 | 只改 `RE3/cfg.py` |
| 一键运行 | `python main.py --size small/medium/large` |
| 消融可替换 | 方法、任务、seed 均由 suite 矩阵声明 |
| 公平比较 | 训练辅助目标与纯任务验证 loss 分离 |
| 可恢复 | checkpoint 保存模型、优化器、batch 顺序、计时与损失平衡 EMA |
| 数据隔离 | `data/`、`ckpt/`、`output/` 三个根目录 |
| 无人值守 | CUDA 实测、显存规划、多 GPU 波次、控制台转发、失败汇总 |

## 2. 模块

```text
main.py
├─ cfg.py                         # 唯一人工配置
├─ preflight.py                   # CUDA/磁盘/数据/反向梯度探针
├─ suite.py                       # 1/7/27-run 矩阵
├─ resources.py + scheduler.py    # GPU 检测、自适应 batch、并发调度
├─ research_model.py
│  ├─ ConceptProjector            # 完整 d_ff → 国家/颜色槽
│  ├─ BusTokenAttention           # 无输入残差旁路的 causal attention
│  ├─ GroupedConceptReadout       # 独立 sigmoid、交换/置零干预
│  └─ ConceptSubspaceFFN          # 私有写回 + 概念独占写回
├─ runner.py                      # smooth-max 训练、DualTag 与因果审计
├─ external_tasks.py              # CLUTRR
├─ language_model.py              # TinyStories/FineWeb-Edu
├─ storage.py                     # data/ckpt/output 约束
└─ reporting.py + verdict.py      # CSV/SVG/HTML/JS 与预注册门槛
```

## 3. 可消融单元

| 方法/参数 | 默认 | 作用 |
|---|---:|---|
| `standard` | — | 原始 Transformer |
| `parameter_matched` | 自动宽度 | 参数量对照 |
| `concept_aux` | — | 只加概念监督 |
| `concept_projector` | — | 概念投影 + self-only attention 对照 |
| `concept_bus_v2` | 主方法 | 投影 + 严格概念 attention |
| `slot_dim` | 64 | 每个概念组向量维度 |
| `num_bus_slots` | 2 | 国家、颜色两个并列组 |
| `bus_layers` | 1 | 只在最后一层启用 |
| `concept_residual_dim` | $6.25\%d$ | 概念独占的 FFN 写回维度 |
| `balance_temperature` | 0.25 | smooth-max 对最弱目标的集中程度 |
| `orthogonality_weight` | 0.01 | 国家/颜色投影去重 |

## 4. 目录

```text
RE3/
├─ data/                                  # 下载或生成的数据
├─ ckpt/<task>/<method>/seed*/...         # 恢复点与 final 权重
└─ output/
   ├─ runs/<stage>/<method>/seed*/...
   │  ├─ logs/train.log
   │  ├─ metrics/{train,validation,final}.*
   │  └─ audits/{test_predictions,trace_sample}.*
   ├─ reports/<report_id>/
   │  ├─ summary.csv
   │  ├─ figures/*.svg
   │  └─ dashboard/{index.html,data.js,report.js}
   ├─ resources/
   └─ preflight/report.json
```

`output/` 不保存模型权重或训练语料。checkpoint 按累计训练时间约每 120 分钟覆盖一个恢复点，结束时保留 `final`。

## 5. 训练目标接口

训练记录：`task`、`concept`、`causal`、`projector_orthogonality`、各目标归一值与动态权重。smooth-max 的 EMA 每个 optimizer step 仅按完整 global batch 更新一次，并写入 checkpoint；改变 micro-batch/梯度累积不会改变 EMA 更新频率，恢复后也不会重置目标尺度。

验证与测试只返回纯任务 loss 和任务指标。反事实输出在同一次前向中由概念写回差分得到，避免为三个训练目标重复跑三次完整 Transformer。

计算节省只允许采用语义等价路径：DualTag 周期验证固定取 2,000 条监控子集、最终测试仍取完整 20,000 条；TinyStories/FineWeb 验证固定为 1,024 条序列，不随自适应 micro-batch 改变；常规验证跳过训练专用反事实 logits；LM 最后一步验证直接作为 final validation，避免立即重复一次。`concept_projector` 的 self-only attention 只计算数学上有效的 V/O，但 QKV/O 参数仍完整注册，参数对照不变。

参数匹配宽度搜索及 matching report 使用 meta 张量只统计形状，不临时分配完整模型权重；正式模型的初始化、参数量和训练过程不变。调度器显式分配 CUDA 后若子进程探针失败，立即终止该任务，禁止静默退回 CPU 浪费长跑时间。

RoPE 正余弦采用按设备、dtype 和已见最大序列长度增长的非持久缓存，避免每层每步重复生成；缓存不含可训练参数，也不写入 checkpoint。

## 6. GPU 与日志

`medium/large` 必须通过真实 CUDA 前向/反向探针。调度器先把任务分散到各 GPU，再按显存预算共置；正式 LM 每张卡默认一个进程。micro-batch 可自适应，global batch 固定并由梯度累积补齐。

控制台保持单行且不超过约 120 字符；`train.log` 保留完整固定列：设备、阶段、步数、loss、显存、间隔/累计时间、seed、任务。

## 7. 验证命令

```bash
pip install -r requirements.txt
python main.py --size large --dry-run
python main.py --size small
pytest -q
```

当前单元与集成测试覆盖：严格因果性、无 attention 旁路、完整 FFN 投影、并列概念槽、反事实梯度、参数匹配、损失平衡、checkpoint 恢复、数据解析、GPU 前检、调度和报告。
